# DocumentationStation

> DocumentationStation.

The smallest module here, and the only one that does not work. It is
documented rather than deleted because it is a shape waiting for an
implementation, and because the state it is in is easy to misread.

## What is there

`Source/DocumentationStation.ps1`, twenty lines, one exported function:

```powershell
function Start-DocStation {
    [CmdletBinding(SupportsShouldProcess = $true)]
    [OutputType([bool])]
    param()
    if ($PSCmdlet.ShouldProcess('documentation', 'Generate project documentation')) {
        if (Read-LineC468A) {
            Write-Host "Project documentation generated in the $PSScript/docstation folder." -ForegroundColor Green
            return $true
        }
        else {
            Write-Host "You chose no." -ForegroundColor Red
            return $false
        }
    }
    return $false
}
```

:::danger[`Read-LineC468A` does not exist]
It is not defined in this module, not in any other module here, and not a
PowerShell command. Calling `Start-DocStation` for real throws
`CommandNotFoundException`.

`$PSScript` in the message is not a variable either — the automatic variable
is `$PSScriptRoot` — so it expands to nothing and the message reads
"generated in the /docstation folder".

The test suite says the same thing in a comment beside the case that covers
it.
:::

The one path that works is `-WhatIf`:

```powershell
Start-DocStation -WhatIf
# What if: Performing the operation "Generate project documentation" on target "documentation".
```

`ShouldProcess` returns `$false` under `-WhatIf`, so the missing command is
never reached and the function returns `$false`. That is the only way the
tests can exercise it, and it is what makes this suite hermetic — nothing is
generated and nothing is asked of a person.

## Layout

```text
Documentation Station/
  DocumentationStation.psd1        v0.0.1
  DocumentationStation.psm1        loads Source/ and Source/Feature/PSReadLine
  Source/DocumentationStation.ps1   20 lines
  Test/AllDocSt.Tests.ps1           62 lines
  Readme.md                        empty
```

`Source/Feature/PSReadLine` does not exist. The loader checks with `Test-Path`
and skips it, which is why an import is silent rather than an error — and is a
hint at what `Read-LineC468A` was meant to be: a PSReadLine-based prompt.

## The loader's `-Exclude`

```powershell
foreach ($file in (Get-ChildItem -LiteralPath $path -Filter '*.ps1' -File -Exclude '*.Tests.ps1' | Sort-Object Name)) {
    . $file.FullName
}
```

The exclusion is there because of a real bug, and the comment above it says
so: **the test suite used to live in `Source/`**, which this loop dot-sources.
So `Import-Module DocumentationStation` ran the `Describe` blocks as a side
effect — from anywhere, including from another module's test run.

The suite is in `Test/` now. The exclusion keeps it that way if one is ever
added back here.
