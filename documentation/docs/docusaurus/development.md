# Development

## Prerequisites

| Tool | Version | Why |
|---|---|---|
| **Node.js** | **≥ 26** | Declared in `engines` on both packages. The plugin uses `node:util`'s `styleText` and `fs.Dirent`-based recursion |
| **pnpm** | **12.5.1** | `devEngines.packageManager` in the root `package.json`, with `onFail: "download"` |
| git | any | |

Both are declared with `devEngines`, so a mismatched pnpm downloads the right
one rather than failing:

```json
"devEngines": {
  "packageManager": { "name": "pnpm", "version": "12.5.1", "onFail": "download" },
  "runtime": { "name": "node", "version": "^26.0.0", "onFail": "download" }
}
```

Neither Lua nor LDoc is needed to build the site, despite what the repository
README has historically said — see [The LDoc files](/docs/docusaurus/ldoc).

Neovim is only needed to regenerate the
[colour theme previews](/docs/neovim/color-themes), which are committed.

## Get started

```bash
git clone https://github.com/natebass/QDtb-doc.git
cd QDtb-doc
pnpm install
pnpm build-plugin
pnpm start
```

**`pnpm build-plugin` is not optional on a fresh clone.** `documentation`
depends on `nvim-docusaurus` as `workspace:*`, and its `main` points at
`dist/index.js` — which does not exist until `tsc` has run. Skipping it gives
a module-not-found error from Docusaurus's plugin loader rather than anything
that names the cause.

`pnpm start` serves at `http://localhost:3000/qdtb-doc/` with the `--no-open`
flag already set, so it does not steal a browser window.

## Commands

All of these run from the repository root and are forwarded to the right
workspace package.

| Command | What it does |
|---|---|
| `pnpm start` | Dev server with hot reload |
| `pnpm build` | Production build into `documentation/build` |
| `pnpm serve` | Serve the built site, to check it as it will ship |
| `pnpm clear` | Delete `.docusaurus` and `build` |
| `pnpm typecheck` | `tsc` across **both** packages (`pnpm -r`). Currently fails — [see below](#pnpm-typecheck-fails) |
| `pnpm build-plugin` | Compile `nvim-docusaurus` once |
| `pnpm watch-plugin` | Compile it on change |
| `pnpm swizzle` | Eject a theme component |
| `pnpm deploy` | Push to `gh-pages` by hand — not what CI uses |
| `pnpm write-translations` | i18n scaffolding |
| `pnpm write-heading-ids` | Write explicit `{#id}` anchors into headings |

### Working on the plugin

Two processes, because Docusaurus loads the plugin's **compiled** output:

```bash
pnpm watch-plugin   # terminal one
pnpm start          # terminal two
```

Editing `nvim-docusaurus/src/**` recompiles, but Docusaurus does not reload a
plugin module — restart `pnpm start` to pick up the change. Editing a `.lua`
file under `QDtb/` *does* trigger a regeneration, because the plugin declares
it:

```ts
getPathsToWatch() {
  return [path.join(QDtbPath, "**/*.lua")];
}
```

### Regenerating the theme previews

Only when a file in `QDtb/colors/` changes. Requires Neovim and mini.nvim, and
the script explains the rest — see
[`scripts/dump-theme-highlights.lua`](https://github.com/natebass/QDtb-doc/blob/master/documentation/scripts/dump-theme-highlights.lua)
and [Color Themes](/docs/neovim/color-themes).

## Writing a page

Pages are Markdown or MDX under `documentation/docs/`, with frontmatter:

```yaml
---
title: "Options"
description: "One sentence, used for the meta description"
sidebar_label: "Options"
sidebar_position: 20
---
```

They are listed explicitly in `sidebars.ts`, except the `fish`, `powershell`,
`other`, `docusaurus` and `reference` trees, which are autogenerated — there,
`sidebar_position` and `_category_.json` decide the order.

### Two things the build is strict about

`docusaurus.config.ts` sets `onBrokenLinks: "throw"` and
`onDuplicateRoutes: "throw"`, so a link to a page that does not exist fails
the build rather than shipping a 404. Two consequences:

- **Use absolute doc paths** — `/docs/fish/startup`, not `./startup`. A
  relative link resolves against the page's **URL**, and an index page's URL
  has one fewer segment than its file path, so `./sibling` from
  `docs/x/index.md` resolves to `/docs/sibling`.
- **Watch the category-index convention.** A doc named `index`, or named after
  the folder containing it, *is* that folder's page. So
  `reference/lua/plugins/fold_this/fold_this.md` is served at
  `…/fold_this`, and linking to the path the filename suggests is a broken
  link.

`onBrokenAnchors` is `"warn"`, not `"throw"`, and the config says why:
Docusaurus only discovers anchors from Markdown headings, so an `id` set on
JSX is reported as broken although it resolves fine in a browser. There is one
standing warning from the homepage for exactly that reason.

### Admonitions need bracketed titles

```markdown
:::warning[Two owners]
…
:::
```

MDX 3 dropped the space-separated form. `:::warning Two owners` renders as
literal text — including the closing `:::` — with no error anywhere.

### Headings with fragile anchors

Docusaurus derives an anchor by lowercasing, stripping punctuation and
replacing spaces with hyphens, which produces things like
`#foldmethod--marker-foldlevel--99-foldtext--` for a heading full of code
spans. Where a heading like that is a link target, give it an explicit id:

```markdown
### `foldmethod = "marker"`, `foldlevel = 99` {#folds-global}
```

## When the build fails

| Symptom | Cause |
|---|---|
| `Cannot find module 'nvim-docusaurus'` | `pnpm build-plugin` has not run |
| `No docs found in …` | The generated tree was read mid-write. Every file operation in the plugin's `loadContent` is synchronous on purpose — see [nvim-docusaurus](/docs/docusaurus/nvim-docusaurus#why-it-is-all-synchronous) |
| `Docusaurus found broken links` | A link to a page that does not exist. The message lists both ends |
| `:::note` appearing as text | Space-separated admonition title |
| Stale content after editing the plugin | Restart `pnpm start`; a recompiled plugin is not hot-reloaded |
| Anything odd after a dependency change | `pnpm clear` |

## `pnpm typecheck` fails {#pnpm-typecheck-fails}

It does, and not because of anything in this repository:

```text
tsconfig.json(6,3): error TS5102: Option 'baseUrl' has been removed.
```

`documentation/tsconfig.json` extends `@docusaurus/tsconfig`, and the copy
shipped in Docusaurus 3.10.2 sets `baseUrl` — which **TypeScript 7 removed**.
`documentation/package.json` asks for `typescript: ^7`, so the two are one
major version apart.

`nvim-docusaurus`'s half of the command passes; only `documentation`'s fails,
and it fails on the configuration rather than on any source file. Nothing is
type-checked either way, so the site builds regardless: `docusaurus build`
uses SWC, which strips types without checking them, and `tsconfig.json`'s own
first line says it is not used by `start` or `build`.

Two ways out, neither yet taken:

1. **Pin TypeScript to 6.x** until Docusaurus ships a tsconfig without
   `baseUrl`. The smaller change, and it restores type-checking now.
2. **Stop extending `@docusaurus/tsconfig`** and inline the handful of options
   the site actually needs, with `"paths": { "*": ["./*"] }` in place of
   `baseUrl` — which is the replacement TypeScript names.
