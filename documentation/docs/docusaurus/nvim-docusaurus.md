# nvim-docusaurus

A local Docusaurus plugin, in its own workspace package, that reads
`QDtb/**/*.lua` and writes [`docs/reference/`](/docs/reference) on every
build.

```text
nvim-docusaurus/
├── src/
│   ├── index.ts      the plugin: discovery, writing, logging
│   ├── files.ts      which files, and how they map to pages
│   ├── parsers.ts    comment parsing
│   ├── markdown.ts   rendering
│   └── types.ts
├── dist/             tsc output — what Docusaurus actually loads
└── package.json
```

It is registered with one line:

```ts
plugins: ["nvim-docusaurus"],
```

## What it produces

**One page per Lua file**, mirroring the runtime layout, with the file's
header comment at the top:

```text
docs/reference/
├── index.md                      coverage, and a table per top-level folder
├── init.md
├── after/
│   ├── ftplugin/{6 files}.md
│   └── plugin/{4 files}.md
├── colors/{7 files}.md
├── lua/
│   ├── config/{4}.md  lib/{1}.md
│   └── plugins/{code_style,fold_this,QDtb,session_manager}/…
└── plugin/packages.md
```

Plus a `_category_.json` per directory, so the sidebar is autogenerated with
the right labels and order.

Current output: **39 pages, 30 of which open with a `---` header comment, and
62 documented functions.**

## The design rule

The plugin owns **exactly one directory** and rewrites it from scratch every
build:

```ts
fs.rmSync(outputBase, { recursive: true, force: true });
fs.mkdirSync(outputBase, { recursive: true });
```

That boundary is the whole design, and it is a correction. An earlier version
wrote into `docs/config`, `docs/plugins`, `docs/colors` and `docs/other`
alongside hand-written pages, with a check meant to protect anything manual —
but it cleared those directories *first*, so a hand-written page was deleted
before the check that was meant to save it ever ran.

Prose about the configuration now lives outside `docs/reference/`, and nothing
there is ever touched.

`docs/reference/` is in `.gitignore` for the same reason: it is build output,
and the build produces it from source that is committed.

## What is parsed, and what is not

The reference is built around **the comment block a file opens with**, because
that is the only place in a configuration that says why a file exists.
Functions and their parameters come after it.

### Header blocks

`parseHeader` reads the run of comment lines at the top of a file, and:

- **Prefers `---` lines.** A file that documents itself is read on its own
  terms: the plain `--` notes interleaved with a doc block — `fold_this.lua`
  has one — are working notes, not the description.
- **Falls back to `--`** when there is no `---` block at all, and **flags the
  file as undocumented** so it appears on the reference index's to-do list.
- **Drops decoration and fold markers.** Rules, arrows, box drawing and
  `{{{` / `}}}` are editor furniture.
- **Splits a summary from a description** on the first sentence end that has
  more text after it on the same line, so both
  `--- Autosave Configuration.` and
  `--- Editor Options. Configures Neovim UI, …` come out right.
- **Reflows the rest into paragraphs**, because Lua comments wrap at the
  source's line width and a column of fragments does not read as prose.

### Functions

`parseFunctions` reads declarations and the comment block above each one.

**`@param` and `@return` types are read by balancing parentheses**, so
`fun(bufnr: integer): boolean` comes out as one type rather than leaving
`integer): boolean` in the description. A named return —
`@return integer saved The number of buffers written` — has its name split
from its prose.

**A function counts as a module function only when it is a statement or has a
qualified name.** `function M.save_all()` and `M.format = function()` do;
`callback = function(args)` inside someone else's options table does not.
Without that rule, 16 autocmd callbacks and picker mappings were documented as
if they were the module's API.

**A local helper only gets a section when someone wrote something about it.**
Everything exported gets one regardless, because that is the API.

### Escaping

Generated pages are `.md`, which the site parses as CommonMark, so braces need
no handling — but angle brackets do. Neovim comments are full of `<C-s>`,
`<leader>` and `<confirm>`, and CommonMark reads those as raw HTML tags and
drops them. Everything interpolated is escaped; table cells also escape the
pipe.

### Link paths

Docusaurus applies a category-index convention: a doc named `index`, or named
after the folder containing it, *is* that folder's page. So
`reference/lua/plugins/fold_this/fold_this.md` is served at
`/docs/reference/lua/plugins/fold_this`, and a link built from the file path
is a 404 that `onBrokenLinks: "throw"` catches. `docsUrl()` applies the same
rule.

## What is skipped

| Skipped | Why |
|---|---|
| `doc/` | Vim's generated help |
| `parser/` | Compiled tree-sitter objects |
| `colors/domscheme-main/` | A vendored terminal-palette drop |
| `node_modules/`, `.git/`, `.vscode/`, dotfolders | |
| `dkjson.lua`, `dump.lua` | Third-party Lua and tool output — [described by hand instead](/docs/docusaurus/ldoc) |

## Why it is all synchronous

Every file operation in `loadContent` is deliberately synchronous, and the
code says so:

> Docusaurus runs all plugins' `loadContent` concurrently (`Promise.all` in
> `core/lib/server/plugins/plugins.js`), and the docs content plugin reads the
> very directory this method deletes and rewrites. Blocking the event loop is
> what keeps that regeneration atomic from its point of view; awaiting
> anything in here lets it observe a half-written docs tree and fail with
> "No docs found in …".

Directory traversal is a recursive `readdirSync`, and the result is sorted —
so the generated tree is byte-identical between builds on machines whose
filesystems enumerate directories in different orders.

## Output

```text
🔌 nvim-docusaurus: reading /…/QDtb-doc/QDtb
   39 pages (30 with a header comment, 62 functions) → docs/reference

   no header: after/ftplugin/javascript.lua
   no header: after/plugin/other.lua
   no header: colors/nordstone.lua
   no header: init.lua
   …
```

Colour comes from `node:util`'s `styleText`, which drops the escape codes by
itself when the stream is not a TTY — so CI logs stay readable without a
`process.env.CI` check.

The undocumented list is printed on every build on purpose. It is short, it
shrinks when someone writes a header, and it is the same list the
[reference index](/docs/reference#undocumented-files) shows.

## Options

Three, all with defaults, and none currently passed:

| Option | Default |
|---|---|
| `QDtbPath` | `<siteDir>/../QDtb` |
| `outputDir` | `"reference"` |
| `sourceBaseUrl` | `https://github.com/natebass/QDtb/blob/master` |

To override one, replace the string form with a tuple:

```ts
plugins: [["nvim-docusaurus", { outputDir: "api" }]],
```

## Adding a header comment

The plugin reads what is there. To improve a page, improve the file:

```lua
--- Autosave Configuration.
--- Writes modified file buffers when Neovim loses focus or is about to exit.
--- @module "plugins.QDtb.autosave"
local M = {}
```

First line the summary, the rest the description, `@module` the name. Without
`@module`, a name is inferred from the path — dotted for files under `lua/`,
since those are the ones on Lua's package path, and the path itself otherwise.
